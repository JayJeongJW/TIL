# 2026-11-15 QA 수업 정리 — 펫 시스템 TC 카테고리 작성 실습과 피드백

> 수업 필기, 직접 작성한 `SBS게임_펫 시스템_TC_정재우_261115.xlsx`, 강사님 피드백을 바탕으로 정리한 기록이다. 오늘은 TC 전체 작성이 아니라 Main·Sub·Detail·Precondition 분류를 중심으로 실습했다.

## 1. 오늘 수업과 실습

- **참고 자료:** `운빨존많겜_홈_TC_이상민` 작성본
- **사용 양식:** `게임명_컨텐츠명_TC_이름_날짜(YYMMDD)`
- **실습 파일:** `SBS게임_펫 시스템_TC_정재우_261115.xlsx`
- **기준 자료:** 이전 수업에서 정리한 교육용 펫 시스템 기획서 및 계층정리 내용
- **작성 대상:** 펫 성장, 펫 합성, 펫 컬렉션

이전에 정리한 계층을 TC 템플릿의 **Main Category, Sub Category, Detail Category, Precondition**에 맞게 옮겨 적는 실습을 진행했다.

처음에는 참고용 운빨존많겜 TC를 보면서 Step도 비슷하게 작성했다. 이후 강사님이 **이번 실습에서는 Step을 작성하지 않아도 된다**고 안내하셔서, 제한된 실습 시간에는 카테고리와 Precondition 작성에 집중했다. 따라서 이번 파일은 TC 전체를 완성하거나 테스트를 수행한 결과물이 아니다.

## 2. 작성하면서 어려웠던 부분

계층정리한 내용을 TC 양식으로 옮길 때부터 어느 항목을 Main, Sub, Detail에 넣어야 하는지 헷갈렸다.

특히 다음 판단이 막연했다.

- 큰 기능을 Main에 적고, 그 아래 어떤 기능을 Sub로 나눠야 하는지
- Detail에 기능의 종류를 적는지, 레벨이나 등급처럼 더 세부적인 조건을 적는지
- 기획서에 있는 '최대 4개', '노출', '미노출' 같은 규칙이나 결과를 Precondition에 그대로 적어도 되는지
- 어느 정도까지 나눠야 상세하게 작성한 것인지

작성하면서도 **Sub·Detail·Precondition을 구분하는 기준이 아직 명확하지 않다**고 느꼈다. 다만 기획서에 적힌 조건을 최대한 빠뜨리지 않으려고 계층을 세분화해서 작성했다.

## 3. 이번 실습 파일에서 작성한 방식

### 펫 성장

- 레벨 → 말풍선 → 1Lv~5Lv → 노출·미노출 구분
- 레벨 → 스킬 습득 → 1Lv~5Lv → 습득·미습득 구분
- 레벨 → 스킬 발동 확률 → 레벨별 항목 구분
- 경험치 관련 항목도 계층에 맞춰 작성

### 펫 합성

- 펫 인벤토리 → 합성 페이지 → 카드목록
- 카드 등록 조건을 동일 등급 카드 4개 이상·미만, 합성창 등록 상태 등에 따라 구분
- 자동 등록, 수동 등록, 카드 해제, 합성 가능 조건을 개별 항목으로 나눠 작성

### 펫 컬렉션

- 펫 컬렉션 리스트 → 펫 컬렉션 구조 → 필요 펫 수·효과 수
- 필요 펫 최대 4개, 효과 최대 2개 등 수치 규칙 작성
- 효과 발동·미발동 조건과 한글·영문 이름의 글자 수 범위·초과·미만 조건 작성
- 컬렉션 효과, HUD 관련 항목도 구분

위 내용은 **실습에서 사용한 분류의 일부**다. 작성한 카테고리가 모두 정답으로 확정됐다는 의미는 아니다.

## 4. 수업 중 추가로 배운 내용

### Step 작성

강사님은 Step을 작성할 때 **Precondition을 기준으로 거꾸로 생각해 실제 테스트를 진행하는 경로와 조작 순서를 상세하게 작성하는 방식**을 설명했다.

이번에는 Step 전체를 작성하는 단계까지 진행하지 않았으므로, 이후 TC 작성 실습에서 실제로 적용해 볼 예정이다.

### Category에 '구조' 사용

강사님은 **TC 카테고리에 '구조'라는 표현을 사용하지 말 것**을 안내했다.

계층정리할 때 '구조'라는 상위 묶음을 사용했던 부분도, TC로 옮길 때는 실제 검증할 기능이나 항목을 기준으로 다시 구분해야 한다.

### UI 기준으로 분류

강사님은 **TC가 보편적으로 전체 UI를 토대로 작성된다**고 설명했다. 화면의 큰 영역과 그 안에 있는 기능을 살펴보면서 Main·Sub·Detail을 나누는 관점을 배우고 있다.

다만 UI 기준만으로 모든 기능과 조건을 설명할 수 있는지는 이후 실습에서 더 확인할 부분이다.

## 5. 강사님 피드백

이번 작성본에 대해 강사님께 받은 피드백은 다음과 같다.

- **카테고리 구분을 잘했다.**
- **경험치 부분은 E열과 F열의 내용을 바꾸면 더 좋겠다.**
- 전체적으로 계층을 세분화해서 **조건을 하나하나 모두 작성하려고 한 점이 매우 좋았다.**
- 중요한 것은 **어느 상위 카테고리 아래에 어떤 하위 카테고리가 들어가는지**, 그리고 **그 하위 카테고리에서 조건을 얼마나 상세하게 나누어 작성하려고 했는지**라는 설명을 들었다.

지난 계층정리 실습에서 '정리가 필요하다'는 피드백을 받았는데, 이번에는 상위·하위 카테고리를 구분하고 세부 조건을 많이 찾아 적으려고 한 부분을 긍정적으로 평가받았다.

특히 처음에는 지나치게 세분화한 것이 아닌지 걱정했지만, 이번 수업에서는 **기획서의 세부 조건을 놓치지 않고 각각 분류하려는 과정**이 중요하다는 점을 알게 됐다.

## 6. 오늘의 개인 회고

참고 TC가 있고 이전에 계층정리한 내용도 있었지만, 그 내용을 새 양식에 옮기려니 여전히 고민되는 부분이 많았다.

Main은 어느 정도 찾을 수 있어도, 그 아래에서 Sub와 Detail을 어디까지 나눠야 하는지, Precondition에는 어떤 상태나 조건을 적어야 하는지 자신이 없었다. 그래서 우선 기획서에 있는 내용을 빠뜨리지 않으려고 레벨, 등급, 수량, 가능·불가능 조건을 하나씩 나눠 적었다.

강사님은 이런 식으로 세부 조건을 하나하나 찾아 작성한 점을 좋게 봐 주셨다. **구분을 잘했다는 평가를 받았지만, 내가 스스로 각 계층의 차이를 확실하게 설명할 수 있는 단계인지는 아직 모르겠다.**

특히 경험치 부분처럼 상위·하위 위치를 조정해야 하는 항목도 있어, 다음에는 내용을 많이 적는 것뿐 아니라 **그 내용이 왜 해당 카테고리 아래에 들어가야 하는지** 생각하면서 작성하려고 한다.
